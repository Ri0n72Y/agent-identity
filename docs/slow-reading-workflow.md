# 慢阅读：执行流程、认知演进与记录方式

> **状态：** 已确定的通用执行流程设计，不代表已部署自动化插件或已经验证认知收益。
>
> **作用：** 指导 Agent 逐步接触长文本，在信息尚不完整时形成暂时理解，随着新内容到来修正判断，并保留必要的理解过程。
>
> **归属：** 本文与[记忆工作流程](memory-workflow_ZH.md)并列。它描述**阅读时怎样工作**，不建立新的身份、记忆或任务执行框架。具体阅读源、会话和记录由使用它的 Harness 与项目工作区管理。

## 1. 核心思路

慢阅读（Slow Reading）的“慢”不是降低输出速度、增加推理 Token 或每读一段都写长篇分析，而是**让理解在文本逐渐展开时形成**。

通常的全文处理是先拿到材料，再直接给出总结或答案。慢阅读则保留一个重要阶段：**在不知道后文时，先认真理解已经读到的内容**。它允许不确定、暂时判断和合理预期；当后文出现时，再辨认哪些判断得到支持、哪些需要更正。

最简流程：

~~~text
确定阅读目标与材料
          |
          v
     获取下一段内容
          |
          v
  形成当前的暂时理解
          |
          +-- 有问题？保留未解之处
          |
          +-- 有依据？可作出暂时预测
          |
          v
    留下必要的阶段记录
          |
          v
       继续阅读
          |
          v
  新信息与旧理解相互比较
          |
          +-- 保留 / 加强
          +-- 细化 / 修正
          +-- 否定 / 暂缓判断
          |
          v
    更新当前理解并保留历史
          |
          +-- 尚未结束 → 继续阅读
          |
          v
  整理全文理解、未决问题与来源
~~~

这是一套可以用于小说、论文、技术文档、设计讨论和其他连续材料的工作方法。并非每种材料都会产生悬念或预测；不应强行制造。

## 2. 元素与职责

| 元素 | 回答的问题 | 作用与边界 |
| --- | --- | --- |
| **Source（来源）** | 正在读什么？ | 原文、文档或连续材料。来源本身与 Agent 的解释分开保存。 |
| **Segment（阅读单元）** | 这次读到哪里？ | 可以是段落、章节、场景或语义完整的小节；根据材料自然切分。 |
| **Visible context（当前已知内容）** | 形成判断时已看到哪些材料？ | 已阅读的原文、相关背景以及先前记录；尽可能区分原文与外部知识。 |
| **Interpretation（暂时理解）** | 目前认为发生了什么、作者在说什么？ | 有依据但可改变的当前判断；不把推测写成事实。 |
| **Open questions（未解问题）** | 现在还有什么不清楚？ | 保存重要歧义、冲突、缺口；没有就不必填写。 |
| **Expectation（预期，可选）** | 基于现有内容，接下来可能是什么？ | 只在有理由时形成，不要求每段预测。 |
| **Revision（修订）** | 新内容让哪个判断发生了变化，为什么？ | 连接前后解释和新依据，不追溯改写原有记录。 |
| **Reading trace（阅读历程）** | 当时如何理解、后来如何变化？ | 必要阶段的时间顺序索引；不是完整对话或隐藏推理的复制。 |
| **Current understanding（当前理解）** | 继续阅读时应带着什么认识？ | 便于延续的简短当前状态，可更新；不替代已有历史。 |

这些元素是**语义角色**，不是新增的固定文件、数据库表或必须填写的九种字段。

## 3. 执行流程

### 3.1 确定目标与阅读边界

开始前，先明确这次阅读的目的。例如理解故事、研究作者的论证、审阅技术方案，或者与用户一起逐章讨论。

确认阅读来源和起始位置。按作品和任务选择自然的阅读单元，不预设每段的 Token 数或必须阅读多少段才能停顿。

如果希望获得真正的“读到这里还不知道后面”的过程，**先只向模型提供当前阅读单元**；不要把全文输入后，再要求它假装不知道后文。由支持逐段读取的工具或 Harness 控制材料揭示会更可靠。

对于已经出现在模型可见上下文中的全文，只能进行**分阶段回读与重新分析**，不能声称这些阶段性想法形成于真实的后文未知条件。模型可能已有的预训练知识也不能通过提示词消除。

### 3.2 阅读一个单元

阅读当前单元时，优先回答：

- 到目前为止，哪些内容可以直接确认？
- 当前最合理的解释是什么？依据来自哪里？
- 有没有会影响继续阅读的重要空缺、矛盾或歧义？
- 如果后文有多种可能，是否需要保留多个暂时解释？

不要把阶段性阅读变成逐句复述。已足够清楚的段落可以轻量通过；遇到转折、歧义、关键证据或理解变化时，再留下较完整的记录。

必要时可以预测后文，但应说明它是基于已知信息的**预期**，不是已经揭示的事实。小说可能需要保持悬念；技术材料则更可能记录假设、前提或待验证接口。

### 3.3 在继续前保留重要判断

一旦形成了对后续理解有影响的判断、疑问或预测，应在进入下一单元前留下简短记录。

重要的是**先有当时的解释，后有新的依据**。不要求每一个自然段都强制落盘，也不要求统一使用结构化表单。没有值得保留的变化时，可继续阅读，只记录已读位置。

如果阅读任务有明确的逐段隔离要求，Harness 可以设置“先记录、再揭示”的门禁；普通阅读工作不必为此新建服务或事务系统。

### 3.4 新内容到来后比较和修订

继续阅读时，首先理解新内容，再判断它与先前的解释之间是什么关系：

- **支持**：先前判断得到新的证据。
- **细化**：方向大致正确，但需要补充条件或修正范围。
- **矛盾**：新证据否定了旧判断的重要部分。
- **悬而未决**：现有证据仍不能排除多种可能。
- **重新解释**：旧段落的意义因后文出现而改变。

发生重要改变时，记录**改变的内容、触发它的新信息、现在的理解**。保留原始阶段记录，不用后来的认识冒充早期就已知晓的事实。

错误解释可以保留为历史，但不能因为错误具有“演进感”而把它当成好的理解。是否值得纠正，要看材料和论证本身。

### 3.5 继续、暂停、恢复与完成

**继续**：带着当前的简短理解、未决问题和必要历史引用读取下一单元。已解决且不会影响后文的细枝末节不必反复注入上下文。

**暂停**：保留来源、已读范围、当前暂时结论及最重要的未解决事项。用户下一次回来时可以从这个状态继续，而不是重新读全篇。

**恢复**：先检查当前来源和既有记录是否一致；有变更则标明新版，避免在两个不同版本之间无说明地推演。

**完成**：先给出对全文的整体理解，再说明重大解释变化、仍有争议的问题和重要来源位置。阶段记录是最终理解的依据之一，不要求把全部阅读历程无差别地倒入最终答案。

## 4. 阅读历程与可读记录

沿用 Amadeus 已使用的“时间头部 + 自然语言”风格，作为人可读的阅读记录：

~~~text
[日期][项目[:会话]][时间][来源:位置]
当前理解与依据。
尚未解决的问题（如有）。
预测或待验证判断（如有）。
~~~

发生修订时，用新条目说明：

~~~text
[日期][项目[:会话]][时间][来源:位置]
新读到的内容：……
此前判断：引用之前的记录……
变化：保留 / 细化 / 修正 / 否定……
当前理解：……
~~~

示例（虚构情节，仅展示记录方法）：

~~~text
[2026-11-01][reading:story][14:05][chapter-02]
叙述者说房间一直无人，但桌上的热茶与此不符。
当前理解：可能有人刚刚离开。
未解问题：门是否允许从外面离开？

[2026-11-01][reading:story][14:12][chapter-03]
新信息：门从内部反锁，且房间长时间没有开启。
修订：此前“有人刚离开”的解释缺乏支持。
当前理解：需要重新考虑时间顺序，暂时不选择唯一答案。
来源：chapter-02 → chapter-03
~~~

这里的头部是**阅读索引的展示样式**，不是与 Short 或 Episode 混用的强制解析 Schema。不同 Harness 可以把来源位置、引用和时间存入已有的会话记录或项目文件。重要的是能够区分“当时说过什么”和“现在怎么看”。

## 5. 与记忆架构的关系

慢阅读是一种**工作中的认知流程**，不是新增的记忆层。

它可以与现有记忆设计衔接，但不自动触发身份变化：

~~~text
Source → 逐步阅读 → 当前理解 / 阅读历程
                           |
                           +→ 当前会话：继续工作
                           |
                           +→ 重要跨会话状态：Short
                           |
                           +→ 值得长期保存的历史：
                               按既有固化流程处理
                               Short → Reflection → Episode
                                                   |
                                                   v
                                                  Diary
~~~

- **原文与具体事实**由来源文档、项目工作区及必要时的 Bookshelf 承担；阅读记录引用它们，不另造事实库。
- **当前会话**保存正在阅读的内容和即时理解；需要跨上下文延续的少量状态可以进入 Short。
- **Episode** 只有在现有固化流程判断值得长期保存时才创建；按既有规则分为 Experience 或 Event，并同步更新 Diary。不是所有阅读段落都成为 Episode。
- **mPFC / SOUL** 只有在相关 Experience 为自我认识提供了有意义的证据、并经过相应身份反思与审核时才可能改变。慢阅读中的预测、误解或精彩表述不会直接更新身份。

本仓库维护这套流程的**设计说明**。实际会话、阅读历程、原文和检索由使用它的 Harness 与对应工作区持有。复用现有 Session、文件、搜索和状态保存能力，不为慢阅读复制一套任务调度器、记忆数据库或身份服务。

## 6. 常见失效方式

| 失效方式 | 处理原则 |
| --- | --- |
| 全文已经可见，却假装首次逐段阅读 | 明确标注为回读或分阶段分析，不把模拟未知当成真实未知。 |
| 每段都被迫预测、发现悬念、写长篇感想 | 只在有实际歧义或重要判断时记录；允许没有变化。 |
| 新信息出现后覆盖此前的错误解释 | 当前理解可以改，历史记录应保留；用新增条目说明修订原因。 |
| 只积累记录，从不重新评价 | 新信息对旧判断有实质影响时，必须比较、修订或保留未决状态。 |
| 把所有阶段解释直接拼成最终总结 | 最终答案重新综合已见证据，引用关键演进而非罗列全部日志。 |
| 把模型的解释文本当成内部思维实录 | 阅读记录是可观察的文本承诺，不是隐藏认知过程的直接测量。 |
| 把每次阅读都导入长期记忆或人格 | 按现有 Short / Episode / mPFC / SOUL 边界选择，不自动晋升。 |
| 为了恢复阅读重新加载全部历史 | 优先使用当前理解、未决事项和定位到的旧条目，必要时再回溯来源。 |

## 7. 完成标准与实现边界

一次慢阅读在以下条件下可以视为完成：

1. 已按本次任务的阅读范围接触并理解所需原文；尚未阅读的部分没有被冒充为已读。
2. 能够给出由实际材料支持的当前整体理解，必要时说明重要的其他解释。
3. 重要判断变化可以回溯到相应的新材料；较早的原始记录没有被后来的结论覆盖。
4. 仍未解决的问题被清楚保留，而不是为了形式上的完整而编造答案。
5. 阅读的当前状态已经交付给用户，或保留在用户可以恢复的项目／Harness 状态中。

文档定义的是**执行语义**。可以由 Agent 手动遵循、由 Skill 指导，或通过支持分段读取的 Harness 实现；是否需要插件、自动保存和访问门禁，应由具体环境的实际能力决定。

**核心原则：先读到什么，就只据此理解什么；遇到新材料时修正认识，而不是重写过去。**
