# Evidence-led UI design（v0.2 · 待专业与用户验证）

目标是设计**连贯、可理解且符合产品体验目标**的界面，而不只是生成合格的页面。Understand → Explore → Materialize → Evaluate 是可回返的思考循环，不是必须完成的四张表。遵循项目约束；只做研究或评审时不修改 UI 代码。

## Understand：理解整个体验

从真实需求、现有产品、代码、组件、反馈和使用条件出发，先识别**用户最终想实现什么**；不要把需求里的按钮或页面清单直接视为最佳问题定义。

当涉及多步骤、跨界面、长期使用或关键状态时，建立**最小 Experience Model**（在分析中说明即可，无需创建文件）：
- **目标与体验意图**：用户最终成果；希望形成效率、掌控感、探索感、信任或成就感中的哪些体验，为什么。
- **对象与关系**：用户以为自己在操作什么，操作属于哪个对象；界面如何让这种理解成立。
- **时间与连续性**：创建、进行、切换、返回、中断、撤销、失败、恢复后，哪些内容和状态必须保持可理解。
- **反馈与预期**：用户应看到什么，才知道系统发生了什么、下一步能做什么。

分别考虑**领域知识、软件操作熟练度、使用频率/经验**，不以“新手/专家”二分代替。短小的局部变更只需确认受影响的上下文；已有充分证据时不强行扩展调查。将观察事实、工作假设和未知条件区分开。

**进入探索的条件**：能指出当前要改善的体验及其主要约束；缺失不影响方案选择的信息可标注假设并继续。

## Explore：挑战默认方案，比较真实取舍

在重要的结构或体验取舍存在时，先问“用户能否以更合适的方式完成目标”，必要时重新定义问题。调查少量任务相近的真实参考，解释能借鉴什么、为什么适用、什么地方不适用。截图是设计参考，不是 UX 成功证据。

探索**不同的交互模型或信息关系**，让视觉层级、排版、色彩、空间、文案和动效与操作反馈**同时演进**。对重要候选方向，指出一个具体的视觉/交互特征：它让用户更容易理解或感受到什么、可能造成什么误解。比较任务路径、对象可理解性、跨状态连续性、视觉/情绪体验、学习成本和实现代价；不要以换色冒充不同方案。

可以选成熟模式，也可以有依据地创新。若现有设计已明确、只是小修复，直接沿用，不强制做多套候选、不为反模板化而牺牲熟悉性。

**进入实现或形成方案的条件**：已经说明所选方向及关键取舍，并知道哪些假设要验证；必要时先做低保真草图或交互原型。

## Materialize：让方案可以被实际体验

根据任务交付草图、流程、交互原型或真实 UI；**用户只要求方案/审阅时停在相应产物**。使用真实或有代表性的内容；有持续状态的产品展示对象归属、进行中、成功、失败和恢复等影响理解的场景。

视觉不是编码完成后补上的皮肤：布局、信息密度、反馈、动效和内容共同表达对象关系与体验意图。优先使用已有设计系统、组件和平台约定；如果要偏离，指出收益与成本。不要预先搭建庞大设计系统。

**进入评估的条件**：已经有足以观察关键操作与重要状态的具体产物，或明确哪些尚未呈现、只能纸面评估。

## Evaluate：验证体验而不自封成功

有可运行产物时，**观察真实渲染和操作**，不只检查 JSX/CSS。对重要或新的操作用 [轻量认知走查](references/02-evaluation.md)：目标意图、发现操作、理解关联、辨认结果；跨页面/会话时另检查对象归属、连续性与恢复。让专业审查关注整体体验、视觉表达和设计风险，技术检查覆盖可复现行为。

对适用 WCAG 的 Web 界面，键盘可操作、可见焦点、正确控件语义等**适用基本要求不因任务小而可选**；只把检查范围限制到变更及受影响的流程，不把局部检查冒充全站合规。根据产品风险扩展设备、读屏、窗口、输入、性能等验证。

报告区分：**已复现的行为故障**（附证据）／**专业或启发式设计风险**／**未获用户确认的假设和偏好**。AI 或专家走查不能代替目标用户独立使用；纸面推演不等于真实验证。

## 按变化规模裁剪、回收经验

- **小修改**：沿用已有模型和规范，检查局部结果、关联流程及适用基础无障碍；没有结构分歧可跳过方案探索。
- **中等修改**：明确最小体验模型、重要状态与取舍；按需比较方案并验证实际交互。
- **大改版/高风险**：研究跨阶段体验，探索不同方向，进行适当原型与目标用户观察；不机械要求完整 Journey Map。

只保留影响决策的成果：选择及依据、已观察问题、未验证假设、复验状态。确认后的长期规则写回项目**现有** UX/设计文档（如 UX.md、DESIGN.md），不另造事实源。遇到不确定或结果冲突，回到 Understand/Explore 修改判断；不因已生成漂亮页面就结束。
