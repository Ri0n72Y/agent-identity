# 03｜给专业 UI/UX 设计师的审阅说明

**项目名称：** AI UI/UX 设计方法 Skill v0.1  
**状态：** 调查初稿，尚未在真实项目中验证。  
**我们希望获得的不是“你觉得好不好看”，而是方法上哪些判断专业、哪些错误或缺失、哪些只适合特定场景。**

## 1. 为什么做这件事

当前 AI 写前端的速度已经很快，但开发者不具备完整的设计判断能力。生成的界面常视觉雷同，也会出现操作入口不清楚、状态反馈不充分、异常流程缺失等问题。我们准备让 AI 遵循一套**先调查用户任务、再设计、再通过真实使用检验**的轻量方法。

我们不打算让 AI 取代设计师。这份 Skill 想让 AI 的设计决策可解释、可修改、可积累，也让不懂设计的开发者能够发现部分风险、提出更好的审查问题。

## 2. 请你重点审查的六件事

1. **问题定义**：视觉同质化与可用性差，应当分开处理吗？是否忽略了设计领域更重要的因素？
2. **工作顺序**：用户任务 → 信息结构/交互状态 → 视觉表达 → 原型 → 验证，这个顺序有哪些错误或例外？
3. **设计判断**：参考成熟产品但不直接复制的做法是否合理？如何判断“正确使用成熟模式”与“懒惰套模板”？
4. **评价能力**：`02-evaluation.md` 哪些检查能交给 AI，哪些必须由设计师、真实用户或专门工具完成？
5. **流程成本**：哪些步骤无意义、重复、太重？对于改一个按钮或设置页，哪些可以跳过？
6. **后续实验**：用同一任务比较“直接生成”与“按 Skill 生成”的办法有何偏差？怎样做一个成本低但能有效检验的方法？

欢迎推翻整个流程，而不是仅修改文字措辞。若问题只影响某种界面，请标注适用情境。

## 4. 专业判断与使用者判断的边界

- 设计师评审可帮助我们改正错误的设计方法、结构性缺陷、视觉语言与信息架构问题。
- 用户测试则用于观察实际目标人群是否能完成任务，以及在哪些步骤发生困难。
- 开发者负责核对功能行为、平台约束、技术代价和数据是否真实。
- AI 负责组织材料、生成候选方案、提出待验证问题及记录证据。**AI 不负责宣布自己设计成功。**

## 5. 后续如何复核这份 Skill

请先审方法，不要求现在亲自设计一套 UI。获得反馈后才在真实项目选用两种情形：

- **专业工作界面**（高信息密度、频繁使用），例如录音转写或开发工具。
- **探索型界面**（感受、探索和反馈更重要），例如轻量游戏操作页。

对同一任务分别生成对照方案，控制功能范围，用专业评审和实际操作确认是否改善。当前没有真实测试结果，因而也没有“效率提升百分比”。
