# 01｜调查结论与待验证假设

> 2026-10-22 初稿。区分「外部资料说了什么」和「本包从中提出的工作假设」。不把开源项目自述、社区意见和 UX 研究等同看待。

## A. 问题应当拆开

**A1. 视觉同质化。** 社区开发者讨论了 AI 网站常出现类似字体、配色、卡片、渐变及重复布局的问题。这类反馈真实存在，但属于参与者主观观察，不能直接估计其普遍比例。[R09][R10]

**A2. 用起来不好。** 界面可以看起来精美，仍然缺少状态提示、错误恢复或合乎用户习惯的操作路径。NN/g 指出，AI 使产出更快，但评估滞后时会形成 UX debt；这一解释与 A1 不同。[R05]

**主要矛盾（针对缺乏 UI 专业知识的 AI 开发者）：** 生成成本低，**正确判断设计质量的证据和能力不足**。因此不能只把解决方案设为“生成更好看的图”。这是本调查的分析判断，尚未对具体项目验证。

## B. 调查到的几种实际路线

| 路线 | 可借鉴 | 不足、条件或风险 | 来源 |
|---|---|---|---|
| 提示词引导视觉设计 | 先明确产品、风格、排版和布局，避免完全依赖默认生成 | 若将“风格鲜明”视为最高目标，可能牺牲可识别性和操作效率 | [R01] |
| 多阶段设计 Skill | 分开 `shape`/`critique`/`audit`/`harden` 等工作，避免只做润色 | 功能面广、流程重；部分风格反模式属于作者偏好，不能当普适禁令 | [R02] |
| 设计知识库式 Skill | 迅速查询布局、配色、字体、平台建议 | 目录规模或“推荐设计系统”不等于实际 UX 效果；项目自述不属于第三方验证 | [R03] |
| 长期可读取的 UX 上下文 | 把已知用户需求、领域词汇、研究结论和设计选择提供给 AI | `UX.md` 是 NN/g 提出的假设性文件结构；实际收益及最佳粒度仍待研究 | [R04] |
| 审查与持续验证 | 通过启发式审查、用户任务与实际运行观察发现问题 | 专家审查不能代替用户研究；工具检测只能覆盖部分问题 | [R06][R07] |

## C. 核心判断及依据

**判断 1：先确定用户任务，再处理画面。**
- 依据：NN/g 十项可用性启发式覆盖系统状态、真实世界语言、控制与自由、一致性、预防错误、可见而非记忆等；这些不是纯视觉规则。[R06]
- 工作假设：围绕“用户要完成什么”设计主路径和状态，会比单凭“现代、简洁”的形容词更可评估。
- 未证实：在不同类型产品、不同模型上能提升多少。

**判断 2：界面必须从运行结果中审查。**
- 依据：社区讨论提到把浏览器截图与交互反馈提供给 AI；Impeccable 将设计批评与实现检测拆开。[R02][R11]
- 工作假设：看到真实渲染结果能减少单凭 JSX/CSS 判断引起的遗漏。
- 未证实：需要多少轮截图审查才有收益；不能从截图证明流程可用性。

**判断 3：统一上下文比无限补充提示词更可维护。**
- 依据：NN/g 的 UX-Context Design 指出通用模型缺乏产品、用户和组织研究的具体知识，讨论 `DESIGN.md` 和假设性 `UX.md`。[R04] Google 已公开 DESIGN.md 项目。[R12]
- 工作假设：经审核的设计决策随项目维护，可减少跨会话的反复猜测。
- 边界：尚无本项目对照实验，不应宣称其必然提升 UI 质量。

**判断 4：有时“普通”恰恰是正确的。**
- 依据：关于 AI 网站雷同的社区讨论中，部分开发者反对过度追求差异化，指出标准布局有时有助于理解。[R09]
- 工作假设：区分“低质量套模板”与“有意复用成熟模式”。设计创新需要有产品目标上的理由。

## D. 存在争议，不应强制写入 Skill 的规则

1. **禁用 Inter、卡片、圆角、渐变？** 这些是某些 Skill/开发者反对模板化风格的经验建议，不能直接成为所有产品的禁止项。是否使用取决于产品品牌、平台以及信息结构。[R02]
2. **先设计三套方案？** 发散探索能发现布局替代方案，但小修复或已有成熟设计系统时会徒增成本。
3. **一开始就建全套 Design System？** 既有项目应首先复用当前组件。新产品可按出现的真实一致性问题渐进形成 token，而非预先生成大量未使用规则。
4. **自动化 UX 打分能否替代设计师？** 不行。启发式方法可发现问题，但结果依赖评估者及上下文。即使专家评估也不能替代用户观察。[R07]
5. **“统一视觉”与“差异化”冲突？** 同一产品内部宜一致；不同产品不必共享同一视觉语言。统一不等于僵化。

## E. 建议的验证实验（未执行）

选一个已存在、用户任务明确的界面，保留功能范围不变。对照：
- **A**：当前 AI 原始生成流程。
- **B**：按本 Skill 提供任务、场景和必要的设计参考，审查后再实现。

比较两者相同任务的真实操作，并请设计师在不知道生成方式的情况下独立评审视觉和交互。记录完成情况、误操作、困惑位置、技术问题、专家指出的问题及改动成本。不以单次偏好投票宣称客观结论。对比时尽量保持模型、输入功能范围和实现时间可比。
