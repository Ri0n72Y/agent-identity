# 慢阅读（Slow Reading）研究与实验协议规范

> 状态：v0.1 · 协议设计基线，尚未完成预注册或实证验证。
>
> 适用范围：慢阅读论文、实验执行 Skill、DSH 实验插件及其测试。
>
> 规范关系：本文定义三者共享的**实验语义和执行边界**；[paper-plan.md](paper-plan.md) 定义论文问题、论证和待验证主张；[background.md](background.md) 记录认知科学与 LLM 实践的比较分析。本文不规定具体 DSH API、数据库或模型厂商。
>
> 本文中的“必须”表示实验合规要求；“建议”表示默认实现选择；“待冻结”表示在正式比较实验开始前需要明确并记录的变量。

## 1. 目的与研究边界

慢阅读不是简单地降低生成速度、增加推理 Token，或把一份全文分成多次摘要。

本研究的核心问题是：

> **当 LLM 必须在不知道后文的条件下，逐步形成、提交并修订对文本的暂时理解时，它的最终理解和可观察的解释演进，是否不同于一次性获得全文后的阅读？**

本研究检验的是**文本暴露的时间结构**以及**阶段性解释的持续存在**，不预设慢阅读能提高准确率，也不预设这种过程等同于人类认知。

论文中的 slow reading 特指同时满足以下条件的处理过程：

1. **真实的后文隔离（future blindness）**：在某一阶段提交前，模型及其可用工具没有获得尚未揭示的文本。
2. **阶段性解释（provisional interpretation）**：每次新增材料后形成有限、可修正的当前理解，而不提前追求完整定论。
3. **提交后推进（commit before continue）**：先完成当前阶段的记录，再揭示下一段。
4. **保留演进（persistent interpretive trajectory）**：旧解释与后来的更正并存；新解释不得追溯改写旧记录。

“慢”指信息逐步揭示、解释受阶段约束，**不要求人为设置等待秒数**。

论文不在本阶段检验人格、意识、长期身份连续性，也不把显式阅读记录当作模型内部思维过程的忠实转录。

## 2. 基本概念

- **Source（原文）**：实验的固定文本版本。实验开始后不得对该版本静默改写。
- **Segment（阅读段）**：按照预先确定的规则从 Source 中切出的连续单元；每段拥有稳定序号和原文位置。
- **Reveal（揭示）**：执行环境允许模型访问某段原文的操作。
- **Visible prefix（已揭示前缀）**：截至当前阶段允许访问的原文集合。
- **Reading state（阶段解释）**：模型在当前信息条件下主动提交的、可供后续比较的文本输出。
- **Commit（提交）**：将 Reading state 固化为带来源和阶段标识的历史记录。
- **Revision（修订）**：新材料到来后对较早解释的确认、弱化、否定或细化；通过新记录表达。
- **Trace（阅读轨迹）**：按实际执行顺序连接 Reveal、Commit、Revision 的可审计记录。
- **Run（实验运行）**：一次确定模型、文本、条件、参数和独立执行上下文的实验实例。

必须区分：

- **原文事实上说了什么**；
- **当时可见的材料是什么**；
- **模型当时认为或预测了什么**；
- **后来是否有材料改变了这个判断**。

预测错误是合法实验结果；推测不能写成已见事实。

## 3. 单次慢阅读的执行协议

### 3.1 准备

实验执行环境必须先完成：

1. 固定 Source 的文本版本、内容校验标识和分段方案。
2. 指定 Run ID、实验条件、模型配置、提示词版本和可用工具范围。
3. 创建独立的运行上下文。除当前条件明确许可的材料外，不得带入同一文本的既往讨论或解释。
4. 初始化只能通过 Reveal 增加可见范围的阅读游标。

分段规则、段长目标、是否允许回看先前段落、上下文截断策略均属于**待冻结实验参数**。不得按模型输出内容临时调整分段，再将结果当成预注册的控制比较。

### 3.2 逐段循环

True Slow Reading 的核心顺序必须为：

```text
Reveal(segment i)
    ↓
Observe current permitted text
    ↓
Interpret: current understanding / unresolved tension
    ↓
Optional prediction / calibrated uncertainty
    ↓
Commit(state i)
    ↓
Reveal(segment i + 1)
    ↓
Compare with committed earlier states
    ↓
Record any revision
    ↓
Commit(state i + 1)
    ↓
...
```

每次 Reveal 后，模型先处理**新增信息相对先前承诺的作用**，再形成当前解释；没有相关旧承诺时，不必制造比较或修订。

提交内容建议保持紧凑：

- **当前理解**：在已见材料下最合理的暂时解释；
- **未解问题／矛盾**：哪些信息尚不足、哪些线索暂时不相容；允许填写“无”；
- **预测（可选）**：仅在文本支持明确预期时记录；必须标记为预测；
- **置信程度／不确定性**：用本次实验预先约定的方式表述；
- **对先前状态的变化**：保留、加强、削弱、否定或细化；附对应阶段或证据位置。

不强制每段产生预测、冲突、顿悟或人格意义。输出长度必须有实验配置中的上限，但不在本规范规定固定字数。限制的目的是**避免无边界的反复自述**，不是压制真实的不确定性。

### 3.3 继续与终止

- 在当前段要求提交的状态未成功持久化之前，**必须拒绝**揭示下一段。
- 提交成功后，才能推进游标；同一段重复请求不得造成重复揭示或重复历史记录。
- 前一阶段已提交的记录不可修改。发现记录错误时，新增带引用的修正事件。
- 运行中断后，只能从最后一个可审计的已提交阶段恢复；不能假定未完成的提交已成功。
- 阅读结束后单独生成最终回答／评测输出，不得回写之前的阶段解释。
- 不应强迫模型在每一阶段得出唯一解释；多种可能性可以并存。

## 4. Future blindness：必须由执行环境强制

仅使用提示词要求“假装没读过后文”**不满足** True Slow Reading 条件。

可信执行环境（例如 DSH 插件所接入的 Harness）必须控制可访问原文，而不是仅控制对话窗口显示内容：

- 模型输入只包含当前阶段许可的文本、约定的先前状态和运行说明。
- 文件读取、搜索、检索、工具调用、附件、缓存以及其他可访问入口不得绕过当前 Reveal 游标获得未揭示原文。
- 未揭示段落的摘要、解答、标题、文件名、元数据或派生索引若包含剧透性信息，也视为未来信息。
- Agent 不能直接修改游标、源材料或 Commit 日志来跳过门禁。
- 每次实际发往模型的输入及工具可见性需要留下足以复核的记录。

如果使用模型训练期间可能接触过的著名作品，Harness 只能保证**本次运行的输入与工具暴露隔离**，不能证明模型参数中不存在相关先验知识。正式研究应记录并管理文本熟悉度、训练污染风险；不得把运行时隔离表述为对模型已有知识的绝对消除。

对于失败的隔离检测，应标记该 Run 不符合 True Slow 条件；不能只在后续提示词中补一句“忽略刚才看到的内容”继续作为有效样本。

## 5. 四个实验条件及比较边界

| 条件 | 未来文本的可见性 | 显式持续的阶段解释 | 作用 |
| --- | --- | --- | --- |
| **Whole Reading** | 完整文本从开始可见 | 无强制阶段提交 | 传统完整文本基线 |
| **Chunked Reading** | 仅已揭示部分可见 | 无持久解释承诺 | 检查分段暴露的作用 |
| **Simulated Slow Reading** | 完整文本从开始可见 | 有，使用与 True Slow 尽可能一致的阶段协议 | 比较真实未知与模拟未知 |
| **True Slow Reading** | 未揭示部分不可见 | 有，且提交先于下一次揭示 | 主要实验条件 |

预先指定的比较：

1. **True Slow vs. Simulated Slow**：重点研究未来信息可见性的作用；提示词、阶段数、提交格式与调用节奏尽可能一致。
2. **True Slow vs. Chunked**：研究在后文隔离和分段相同的条件下，持久阶段解释是否产生额外作用。
3. **True Slow vs. Whole**：检验相对于常见全文阅读流程的整体差异，但不能据此单独归因于 future blindness。

**这不是天然正交的完整 2×2 因子实验。** Whole 与其他组的调用次数、分段处理和状态持久化可能同时不同。不得用“控制了其他一切变量”的措辞描述当前设计。

Chunked 条件的精确定义尤其重要：它可以保留已揭示原文，但不能把模型生成的阶段性解释当成下一阶段的显式持久承诺。如果需要最低限度的上下文衔接或压缩，必须预先写清楚其内容以及为何不等同于 Reading state。

Simulated Slow 条件必须真的允许未来文本被模型访问；如果在模型调用层面也只传入逐段内容，它实际上变成了 True Slow，而不是有效的对照组。

## 6. 记录、来源与存储所有权

实验 Trace 是**研究数据**，由执行它的研究项目工作区持有。它不会因为包含长期的解释演进，就自动成为 Amadeus 的 Episode、Diary、mPFC 或 SOUL。未来若要进行记忆整合，应通过独立的项目选择与反思流程，并保留研究原始记录的来源。

沿用双方讨论过的人类可读历史标记：

```text
[日期][文档:运行][时间][阶段]

新信息：
当前理解：
尚未解决：
预测（可选）：
与先前解释相比发生了什么：
来源段落：
```

这个标记是方便审阅的**展示约定**，不是必须用正则解析的唯一存储格式，也不是 Identity 的 Short/Episode 规范。

实验元数据可以用 JSON、数据库或现有 Harness 持久化机制存储。跨实现至少要能恢复以下事实：

| 信息 | 最低要求 |
| --- | --- |
| Run 身份 | Run ID、实验条件、开始/结束状态 |
| 原文 | Source ID、固定版本／摘要校验、分段规则、段序号和位置 |
| 执行配置 | 模型与版本、调用参数、提示词版本、可用工具、上下文/回看策略 |
| 暴露事件 | 实际揭示的段、阶段、时间、许可范围，以及输入／工具可见性证据 |
| 提交事件 | Commit ID、对应 Reveal、文本内容、时间、历史引用 |
| 异常 | 重试、超时、中断、越权暴露、恢复及失效标记 |
| 评测 | 最终输出、评价程序／版本、标注者或评判模型信息 |

**来源、暴露、提交、评测是不同的数据类型。** 不应将它们混成一份只含摘要的 Markdown 记录。外部键与技术字段可以是结构化的；解释演进正文保持简洁自然语言即可。

建议重用已有 Harness 的会话持久化、访问控制、执行审计和文件存储。没有实际缺口时，不创建独立的记忆服务、数据库框架或身份状态机。

## 7. 实验可比性和评价

正式运行前必须冻结、记录并在报告中公开影响比较的主要条件：

- 语料选择、文本版本、排除标准与分段；
- 模型版本、采样参数、提示词模板、独立运行次数与随机化；
- 上下文容量、已见原文回看方式、早期输出如何重放、截断与压缩；
- 各条件每段的调用次数、输入／输出 Token、推理预算及额外反馈；
- 最终回答任务、主评价指标、次要指标以及评分程序；
- 对训练污染、工具越权、失败样本和中断 Run 的处理规则。

不能为了“公平”强行抹掉实验因素必然产生的差异。例如 Simulated Slow 可以看见全文，True Slow 不能，其输入长度天然可能不同。应尽可能控制其他流程因素，并将残余差异列为解释限制。

**结果指标（Outcome）**可以涉及事实、因果、人物意图、主题理解、回忆等，具体任务需先固定；**过程指标（Process）**可涉及预测、置信度、被否定的猜测、修订幅度、长期未解矛盾与锚定效应。

比较规则：

- 主要结论必须依据不同条件都能测量的结果指标。
- 过程轨迹应先分析可观测到相应记录的条件；Whole 或 Chunked 不产出某种承诺记录，**不意味着其内部不存在相应认知事件，更不能把缺失值当作零**。
- “更多修订”本身不意味着“更好的理解”；应检查修订是否与已揭示证据及最终结果相关。
- 模型对自身认知过程的解释属于输出数据，不能当作隐藏思维或神经机制的直接测量。
- 无差异、结果变差、错误锚定和预测失准都必须作为可能的有效结果保留。

## 8. 论文、Skill 与 DSH 插件的职责

**论文**负责给出研究问题、理论来源、实验设计、实际结果、因果解释边界与限制。未经实验不报告结果。

**实验 Skill**负责指示 Agent 的非确定性行为：阅读新增内容、形成暂时解释、允许不确定性、识别变化、简要输出阶段状态。它不能承担访问隔离、不可篡改日志或游标原子推进的安全责任。

**DSH 插件／Harness 集成**负责确定性约束：分段存取、许可范围、Commit 门禁、运行恢复、来源与暴露审计、配置留档。优先调用已有 Harness 能力；仅补充确实缺少的门禁。

三者应引用本协议，避免各自复制出彼此不同的“慢阅读”定义。本文不要求建立通用人格框架、额外的 Agent 团队协议或完整记忆架构。

## 9. 最小验收场景

实现者至少应能在独立测试运行中证明：

1. 尚未提交当前状态就请求下一段时，Reveal 被拒绝。
2. True Slow 的模型输入和可用工具不能访问尚未揭示的源文本。
3. 提交后新段可见，但既有 Commit 原文不可被覆盖。
4. 重复调用 Next、重复提交、超时或恢复，不产生重复事件或越过游标。
5. 先前错误判断能在后续记录中被明确修正，同时保留旧状态。
6. Simulated Slow 允许未来文本可见，且其各阶段的提交协议与 True Slow 一致。
7. 最终输出和各段解释可分别追溯到模型配置、暴露事件及源文本版本。
8. 越权暴露或其他关键协议失败的 Run 会被标记失效，而非静默继续计入研究结果。

通过这些测试只能说明**协议实现满足所测约束**，不能说明“慢阅读改善了理解”。

## 10. 正式实验前待冻结的决策

以下参数仍然开放，不由本规范臆定：

- 测试语料属于叙事、说明文、论证文本中的哪些类型；如何管理已知作品污染。
- Segment 采用段落、章节还是人工边界；是否允许边界自适应。
- 已揭示原文、Commit 历史及其摘要怎样装入上下文；超过容量时怎样处理。
- Chunked 的最低上下文衔接形式；Simulated Slow 的未来文本如何在每轮保持可见。
- 模型/运行配置、重复次数及预算；哪些结果作为主要假设检验。
- 过程指标的具体评分标准、标注一致性及对照评测方法。

这些是**实验设计待办**，不是规范没有生效的理由。可先做少量探索性运行验证协议，再在正式实验前冻结参数。探索性运行与正式统计样本必须明确区分。

## 11. 核心不变量

> **先见到什么、当时如何理解、后来为何改变，必须能够分别查证。**

只要后文没有真正隔离，就不能称为 True Slow；只要旧解释能被重写，就无法可信地研究解释演进；只要把过程丰富误写成理解提升，就偏离了研究问题。

本协议应随着真实实验的失败与发现修订，但每一次改变正式实验条件都必须留下版本记录。
